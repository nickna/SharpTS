# I02: Shared CLR metadata caches

Resolves [#1897](https://github.com/nickna/SharpTS/issues/1897) with demonstrated
ownership fixes and retention of the weak-cache generation designs. Inventory:
`artifacts/epic-1865/I02-source.txt`.

| Stores | Owner, identity and lifetime |
| --- | --- |
| TypeProvider `_typeCache` | Shared provider's default-context name cache. Resolution avoids strong publication for collectible/generated types. Explicit contextual reflection bypasses the default name cache: the same assembly-qualified string can denote another context's type. |
| `_methodCache`, `_ctorCache`, `_propertyCache` | Strong shared caches only for non-dynamic, non-collectible declaring types and signatures. Method name/type/parameter sequence, constructor type/parameter sequence, or property type/name is the lookup identity. Signature arrays are now copied before use as keys. |
| `_emittedTypeCaches` and its member dictionaries | Weak declaring-type owner for generated/collectible metadata; values may reference that owner without rooting it. Framework declaring types with collectible signature arguments bypass strong caching. Recursively constructed generics/element types preserve these lifetime decisions. |
| Fixed lazy framework member fields and `_coreAssembly` | Shared immutable framework identities, safe for provider lifetime. No generated handles belong in these fields. |
| `DotNetSynthesisCache._current`, `_identities` | Replaceable weak type-to-completed-declaration generation, plus weak declaration-to-CLR-type identity associations. A retained checked declaration deliberately retains its imported CLR identity across reset. |
| `DotNetTypeRegistry.CacheGeneration.Names`, `.Members` | Ordinal non-collectible default-context name cache plus weak type-owned member catalogs for methods, properties/fields, events and indexers. Contextual reflection bypasses name-cache reads and publication. Reset swaps the whole generation atomically; in-flight readers retain their captured generation. |
| Returned method/indexer arrays | Now caller-owned copies of private cached arrays. Reflection member handles remain shared completed metadata; editing a returned array cannot alter another lookup. |

`I02-before.trx` preserves three failures: mutating a supplied signature array made a later
identical lookup reflect again; editing a returned method array poisoned the next consumer;
and TypeProvider rooted a non-dynamic assembly loaded in a collectible context. Method/
constructor keys now snapshot non-empty arrays, TypeProvider excludes `IsCollectible`
types from strong caches (including name resolution under contextual reflection), and
DotNetTypeRegistry copies result arrays at its API boundary. Existing shared-array identity
expectations are preserved in the before-source artifact; lifecycle tests now require member
identity, caller array isolation and actual reflection-count evidence that reset rebuilds
catalogs.

Final review reproduced another identity collision in both name caches. Priming a
normal lookup before entering a collectible context returned the normal assembly's
type, including for constructed generic types. `I02-context-before` and
`I02-registry-context-before` preserve the two failures for each resolver. Explicit
contextual scopes now resolve without consulting or publishing the default cache;
the ordinary cached owner remains intact after leaving the scope. Weak member
caches still use the exact resolved CLR type. `I02-context` covers the two new
cases and existing cache/synthesis/reflection lifecycles: **33 passed / 0 failed /
0 skipped**. Quality gates and the zero-warning AOT ratchet pass again for both
context fixes.

No weak cache rewrite was needed. Concurrent lookups publish completed results; exceptions
publish nothing and remain retryable. Synthesis installs the reverse identity association
before publication. Resets preserve retained old metadata without allowing old work to
repopulate the new generation. These caches have lookup/reset boundaries, not a compiler
declaration freeze. They serve reflection metadata, not guest values or emitted declaration
ownership; module/compiler catalogs remain separate.
