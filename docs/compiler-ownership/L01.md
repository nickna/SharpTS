# L01: Arrow and class-expression captures

Resolves [#1889](https://github.com/nickna/SharpTS/issues/1889) with protected binding
selection, one adapter owner and complete static-block arrow collection. Inventory:
`artifacts/epic-1865/L01-source.txt`.

| Stores | Identity and lifetime |
| --- | --- |
| `Analyzer` | One invocation's closure/capture analysis, created before declaration and consumed during collection/body emission; it does not own guest variable values. |
| `ArrowMethods`, `DisplayClasses`, `DisplayClassFields`, `DisplayClassConstructors` | Arrow AST reference identity. Final arrow collection declares either a static capture-free method or a per-arrow display type with constructor/fields/Invoke. The maps describe different artifacts for one callable. Context aliases select the same builders. |
| `ArrowParameterTypes`, `ArrowReturnTypes` | Same AST identity; signature resolution precedes declaration and bodies read those resolved types. The parameter array is construction metadata used inside the compiler, not a process-wide or consumer-editable declaration catalog. |
| `ArrowMethodCounter`, `DisplayClassCounter` | Compilation-local name allocation; names do not replace AST identity. |
| `DirectCallArrowBindings` | Non-escaping analysis hint by name; direct dispatch additionally checks the actual local's display type or reference-identity tag and exact signature/arity. Missing proof falls back to ordinary function values. |
| `ConstArrowBindings` | Now a protected snapshot selected from the complete program before arrow collection. A top-level const arrow is eligible only when its name denotes a single runtime declaration across all input trees. |
| Expression `EnclosingClass`, `CaptureFields` | Expression AST identity owns the lexical enclosing private class and generated capture fields. Body contexts receive the enclosing identity and same field handles; repeated runtime evaluation remains governed by class-definition capture registration. |
| Boxed adapters | One compilation-local cache shared by base/child contexts, keyed by arrow method, delegate arity and return shape. An adapter marshals the existing typed signature and is emitted on its selected program/display carrier. There is no process-wide generated-handle cache or SharpTS.dll token. |

The previous const-name map used last-write-wins across modules and ignored parameter/local
shadows. A parameter named `callback` could be replaced by a different top-level arrow:
the preserved `callback-shadow.ts` returned `101,102` interpreted but `2,3` compiled.
[`ConstArrowBindingAnalyzer`](../../src/SharpTS/Compilation/ConstArrowBindingAnalyzer.cs)
counts runtime bindings, including parameters, destructuring, imports, loops and catch
variables. Ambiguous names use the ordinary callable path. Unique top-level names retain
their direct adapter. The snapshot cannot be changed through a dictionary cast. This is
conservative: unrelated same-named declarations can also disable the optimization.

Two separate function bodies using the same typed arrow previously emitted two identical
`<>Arrow_0$box1` methods on the same program type. The preserved adapter regression fails
with two matches before the change. Base and child contexts now receive the same adapter
emitter from `ClosureCompilationState`; the regression executes both bodies and requires
one method. The static-scope cases also exposed absent arrow methods: class declaration/
expression collection skipped static blocks, making a local callback non-callable. Their
arrows are now collected before declaration; original failures remain in `L01-static-before`.

All modules are collected before capture propagation and display declaration. Constructors
and Invoke handles precede body emission; adapters can still be declared by body consumers.
Script/module finalization creates display types after those bodies. Capture-free arrows
do not require display metadata, and typed/boxed signatures remain distinct. No early
freeze of builders or guest capture values is introduced.

Verification selections: `L01` **124 passed**, `L01-adapters` **55 passed**, and `L01-final`
**282 passed**, zero failed/skipped. New regressions compare both backends and verify script/
module IL for parameter, local, block, loop, catch and destructured-parameter shadows and
same-named modules in both import orders, plus class declaration/expression static scopes.
Reflection tests prove the unambiguous typed callback still emits its direct adapter and
multiple bodies reuse it. Existing arrow, capture, array, static-block and sort regressions
remain valid. Release build and quality gates pass; logs/TRX: `artifacts/epic-1865/L01*`
and `quality-L01.log`.
