# L03: Entry-point and module captures

Resolves [#1891](https://github.com/nickna/SharpTS/issues/1891) by retaining the existing
per-compilation owner and its module-specific views. Inventory: `L03-source.txt` under
`artifacts/epic-1865`.

| Stores | Identity, lifetime and writes |
| --- | --- |
| `EntryPointDisplayClass`, constructor, static instance field | Lazily declared once by `ClosureCompilationState` when a capture exists; one shared emitted type, with a runtime reference used by module initialization and closures. Absence for capture-free inputs avoids an unused type. |
| `ModuleCapturedTopLevelVars`, `ModuleEntryPointDisplayClassFields` | Normalized module path, or the `<single-file>` sentinel for scripts sharing global scope; inner keys are source binding names. Generated field names include module qualification. Repeated registration adds/reuses handles on the same owner. |
| `ModuleTopLevelLexicalInitFields` | Same module/binding identity, with separate boolean initialization fields. Captured lexical flags are DC instance fields; other top-level flags are program statics. A flag describes initialization, not the value slot. Reads check it and declarations mark it only after storing. |
| `ModuleLiftedBlockScopedVars`, `ModuleRegisteredDeclaredNames` | Live per-scope analysis sets. Only uniquely declared, non-loop block lexicals are candidates. Later merged-script registration can revoke a lift before emission when its name collides; retained field metadata can then be reused for a real top-level capture. |
| `CapturedTopLevelVars` | Union for cross-module allocation decisions, not the emitter's lookup authority. Revocation removes a name only when no module still owns it. |
| `ArrowEntryPointDCFields` and context aliases | Arrow AST reference identity selects its relay field. Body/module contexts receive the owning module's field/set views and the actual instance access path, rather than all modules' names. |
| `SelfCaptureWriteBacks` | Declaration-initializer context owns a temporary list of display-instance/field pairs. Closure creation records snapshots; the declaration stores its value, updates those fields, then restores the enclosing initializer's list/name. This is runtime initialization work, not a global declaration cache. |

The registration and revocation paths are in
[`ILCompiler.cs`](../../src/SharpTS/Compilation/ILCompiler.cs); alias selection is in
[`ILCompiler.ContextFactories.cs`](../../src/SharpTS/Compilation/ILCompiler.ContextFactories.cs).
All module/script registration precedes collection and bodies, so revocation is legitimate
analysis mutation. Final type creation follows body emission. The same field handles are
intentional authority; initialization flags and capture sets are different facts. Freezing
the guest DC instance would break closure mutation. Per-iteration bindings use fresh cells/
snapshots rather than one lifted block slot.

Verification: `L03` passed **167** tests for imported modules, merged scripts, same-named
bindings, block shadows, self-reference and loop captures. `L03-lexical` checks forward
lexical references, per-iteration bindings and live module exports: **78 passed**. Both
selections have zero failures/skips. Logs/TRX preserve
execution expectations for both backends; no production change was required.
