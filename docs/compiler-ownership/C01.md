# C01: Class declarations and constructors

Resolves [#1883](https://github.com/nickna/SharpTS/issues/1883) by retaining the current
per-compilation declaration authority. Inspection starts at
[`ILCompiler.State.cs`](../../src/SharpTS/Compilation/ILCompiler.State.cs); the immediate
producer/consumer inventory is saved in `artifacts/epic-1865/C01-source.txt`.

| Store | Identity, writes and lifetime |
| --- | --- |
| `Builders`, `Superclass` | Generated qualified class name; `DefineClass` publishes the builder and resolved ancestry. Module/namespace qualification and generated block names select distinct CLR declarations. `ClassRegistry`, mapper and contexts share these dictionaries, rather than reconstructing a second member authority. |
| `BlockScopedNames`, `BlockScopedBuilders` | Reference identity of `Stmt.Class`; `DefineDeclarationFromStatement` assigns a generated name once and `DefineClass` links that source to its declared builder. Same source names in different scopes do not identify the owner. |
| `Declarations`, `EmittedMethodBodies` | Reference-identity sets. The remaining-declaration collector suppresses a second declaration; `EmitClassMethods` suppresses a second body. Ambient/external declarations intentionally have no generated builder. |
| `Constructors` | Qualified name selects the class's primary constructor. `DefineClassMethodsOnly` predeclares it for forward use; `EmitConstructor` reuses that handle and creates a fallback only if absent. Class expressions publish the same constructor under their generated name. |
| `PrototypeConstructors` | `TypeBuilder` identity; a separately declared constructor creates a prototype object without guest constructor effects. Declaration is idempotent; this is a different operation from the guest constructor. |
| `ConstructorOverloads` | Dormant empty store: the source inventory finds only its declaration, no writer or reader. It is not an independent authority; overload source signatures select the implementation body in the constructor producer. |
| `ErrorSubclasses`, `ArraySubclasses`, `PromiseSubclasses` | Qualified-name derived ancestry decisions populated during declaration and consumed for constructor chaining/property/static fallback. Their absence means ordinary ancestry, not a missing constructor declaration. |
| `CompactStorageClasses` | `Stmt.Class` reference identity; whole-program analysis selects eligible classes before declaration. The set is a representation proof, not another class builder index. |
| Expression `Names`, `Builders`, `Constructors`, `Superclass` | `Expr.ClassExpr` reference identity; collection assigns a unique generated namespace even for named expressions. Expression declarations own their type/constructor, and the qualified-name constructor index is an intentional alias to the same builder. |
| Expression `VarToClassExpr`, `ToDefine`, `Counter` | Binding lookup aid, ordered collection worklist and compilation-local name allocator. A variable's current runtime class value is not inferred solely from the global binding aid; checked expression identity takes precedence for parent resolution. |

The declaration, constructor and body phases are intentionally separate. Constructors and
prototype handles must exist before callers and derived bodies use them. Nested classes can
still be discovered before/during body emission; freezing these maps at the initial declaration
pass would reject valid inputs. Script phase 9 and module phase 11 finalize types after all
bodies and initializers. Existing checked generic/private/property/computed/deferred owners
complete there; `CreateType` closes Reflection.Emit construction. No process-wide store retains
these builders. A fresh compiler owns fresh state; compiler reuse is not a reset contract.

Optional lookup is retained for external/ambient classes and absent superclass/prototype
optimization paths. Required generated constructor/body paths index the already declared
handle. Duplicate source discovery is idempotent; CLR declarations are not redefined under
the same generated identity. There is no demonstrated conflicting independently mutable
authority in this boundary and no new completion gate is added.

Verification: **99 + 255 passed**, zero failed/skipped, in `C01` and `C01-behavior`.
Selections include deferred registry missing/duplicate/late checks, same-named expression
parents across modules, generic constructor identity, async-local classes, ordinary and
expression classes, repeated class definition evaluation, forward references, built-in
Array/Promise/Error ancestry and scalar replacement. Existing module cases verify IL and
execute output; behavior tests exercise both backends. Logs/TRX are under
`artifacts/epic-1865/C01*`. No production behavior changes are claimed.
