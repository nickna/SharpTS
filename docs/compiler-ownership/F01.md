# F01: Generic function declarations

Resolves [#1887](https://github.com/nickna/SharpTS/issues/1887) with an implementation.

The former `FunctionCompilationState.GenericParams` and `IsGeneric` dictionaries used
qualified function names as parallel authorities. Contexts received writable dictionaries
and writable parameter arrays. Namespace import aliases registered the same method under
another name without copying either generic dictionary. A direct alias call could therefore
miss the generic instantiation decision.

[`FunctionGenericParameterRegistry`](../../src/SharpTS/Compilation/FunctionGenericParameterRegistry.cs)
now owns an explicit declaration for each ordinary function's `MethodBuilder` identity.
`DefineFunction` registers the empty non-generic declaration or the ordered parameter
builders after applying constraints. It rejects missing, duplicate, foreign, reordered,
null and arity-mismatched metadata without publishing an invalid entry. Registration
snapshots its input; the returned list rejects collection mutation. The builders remain
emission handles, as in the existing class registry; this does not make Reflection.Emit
objects immutable.

[`CompilationContext`](../../src/SharpTS/Compilation/CompilationContext.Functions.cs) and
child context factories share this owner. Direct calls inspect the selected method's generic
definition and require its registered parameters, including explicit type-argument calls.
Body emission reads parameters by method identity. Lookup aliases cannot change generic
status or ordering. Default-parameter overloads keep their existing signatures and forwarding
policy. Inner functions retain their existing erased representation; async/generator stubs
remain non-generic and can call registered ordinary generic functions.

Registration closes in script `Phase9_FinalizeTypes` and module
`ModulePhase11_FinalizeTypes`, after all body/init emission and before type finalization.
Completion revalidates owner arity/order and rejects repeated completion and later writes.
The registry lives in one compiler instance and contains no process-wide generated handles.

Verification: **110 passed, zero failed/skipped** in the `F01` selection of
`FunctionGenericParameterRegistryTests`, `GenericsTests` and `NamespaceFunction*`.
Tests cover independent/same-named owners, input/output mutation, invalid and late
registration, explicit/inferred direct namespace aliases, nested erased functions,
default-bearing declarations and generic calls across await/yield. The script case executes
saved output without SharpTS.dll; the module case verifies IL and executes it.
Release build succeeded; `scripts/test-code-quality.ps1` passed with zero errors.
Logs/TRX: `artifacts/epic-1865/F01.log`, `F01/F01.trx`, `quality.log`.

An initial exploratory test called a generic namespace function through its runtime value
and hit `ContainsGenericParameters`; that is not a passing value-call assertion or a claimed
repair. The direct-call tests above exercise this boundary. Its original failure is preserved
in `artifacts/epic-1865/F01/initial.trx`; generic value-call semantics are outside F01.
