# I04: Legacy runtime targets and bridges

Resolves [#1899](https://github.com/nickna/SharpTS/issues/1899) by retaining the
bounded late-binding and deployment contracts. Inventories are
`artifacts/epic-1865/I04-sites.txt` and `I04-late-bound.txt`.

`RuntimeEmitter.ReflectionHelpers` owns emission recipes, not a process-wide
cache of generated handles. Each helper MethodBuilder belongs to its supplied
TypeBuilder. Arguments are freshly packed object arrays; the fixed host target
is identified by assembly-qualified type name and public static method name.
The inspected names are unique host methods with the arities below. Their
implementations and the compiler ship together; arbitrary host overload
registration is not supported. No generated builder escapes into this lookup.

| Target family | Identity and availability |
| --- | --- |
| `RuntimeTypes` abort/date | `AbortSignalAnyCompiled(1)` and `FormatDateToLocale(4)` retain the fixed host ABI. Selected features record their managed-runtime requirement. |
| `RuntimeTypes` Intl | Eight `CreateIntl*` factories each take two objects. The optional emitted Intl component owns the generated factory handles; the fixed host factories construct runtime instances. Feature selection controls declaration and deployment. |
| `RuntimeTypes` DNS Resolver | `DnsCreateResolverState(0)`, `DnsResolverSetServers(2)`, `DnsResolverGetServers(1)`, `DnsResolverCancel(1)`, `DnsResolverGetGeneration(1)`, `DnsResolverSetLocalAddress(3)` and `DnsResolverResolve(1)` retain their checked emitted DNS component handles and fixed host targets. The resolution request carries its state and arguments. |
| Proxy | `SharpTS.Runtime.Types.SharpTSProxy, SharpTS` is constructed with target/handler; `RuntimeTypes.CreateRevocableProxy(3)` receives target/handler/undefined. This feature requires the host runtime. Constructor binding remains Activator's fixed host-type contract. |
| Source execution | `SharpTS.Execution.SourceExecutionService, SharpTS` supplies `RunJson(3)` and `ConfigureUntrustedProcess(1)`; the latter's invoke result is discarded. The optional emitted component retains exactly its selected handles and reports the runtime requirement. |
| Other frozen direct sites | Worker/Atomics interpreter fallbacks, JSON Proxy trap materialization, process environment helpers, child-process fork, cluster worker bridges, VM interpreter calls and eval retain their explicit fixed SharpTS type/method strings and existing source allowlist. Their individual feature gates and deployment flags remain authoritative. |

The generic static-call recipe checks a missing host type and emits a named
`InvalidOperationException`, or an explicit caller-provided terminating fallback.
Proxy construction is a required-host path, not an optional no-host fallback.
The generated assembly does not acquire a SharpTS metadata reference from these
strings. Normal CLI deployment copies SharpTS only for required capabilities;
`--standalone` suppresses copying without erasing those requirements. Native AOT
rejects unavailable managed-runtime capabilities. A host-required feature is not
claimed to execute without its host merely because the assembly has no hard
SharpTS reference. VM, cluster, Intl and source-execution tests cover that
distinction, including deliberate absent-runtime behavior.

DNS result-order synchronization is intentionally different. The emitted
`_dnsResultOrder` field belongs to each generated runtime; writes validate guest
configuration and update that field. A best-effort late-bound
`RuntimeTypes.DnsSetDefaultResultOrder` call synchronizes the host's process-level
`DnsConfig` when available, and is guarded when unavailable. Hosted promise and
resolver paths consult that host configuration. Ordinary embedded lookup can
execute without SharpTS. Process-level guest configuration is mutable runtime
state, not a metadata registration catalog to freeze. Resolver servers, local
addresses and cancellation generations belong to each resolver instance; the
host does not promote them into shared generated metadata.

Host reflection caches retain CLR member identity and existing weak-key
lifetimes. Resource disposal's managed callable fallback remains open-world.
Runtime object/Proxy state belongs to its object; caller arguments and resolver
requests remain invocation state. Metadata component completion requires all
selected declarations before use, while their bodies are emitted afterward.
Independent assemblies retain separate DNS fields and component handles.
Existing component tests cover missing, null, duplicate, incomplete, absent
feature and cross-compilation operations. No additional registry or completion
phase is needed for the fixed string targets, and no unresolved defect was
identified in this frozen boundary.

Verification: `I04` **106 passed**, `I04-standalone` **17 passed**, and
`I04-deployment` **22 passed** for additional isolated DNS, source-execution and Proxy
checks. All have zero failures/skips. The selections exercise actual execution,
host deployment and no-host execution/failure paths, source allowlists and saved
IL. The consolidated verification ledger records the final counts. No production
change was required.
