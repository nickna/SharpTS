# C02: Public class members

Resolves [#1884](https://github.com/nickna/SharpTS/issues/1884) with a retention decision.
[`ClassCompilationState`](../../src/SharpTS/Compilation/ILCompiler.State.cs) owns the
declarations; [`ClassRegistry`](../../src/SharpTS/Compilation/Registries/ClassRegistry.cs)
and context factories receive references to those stores. They do not copy builders into
an independently writable registry. Inventory: `artifacts/epic-1865/C02-source.txt`.

| Stores | Authority and permitted writes |
| --- | --- |
| `StaticFields`, `InstanceFieldsField` | `DefineClass`/expression definition own fields by generated class name. Static guest fields and the instance dynamic-storage field are distinct CLR declarations. |
| `StaticMethods`, `InstanceMethods` | Qualified class and source member names select declarations. `DefineClassMethodsOnly` declares implementations, skipping overload signatures, private and computed members. Its class-level/per-static-member guards reuse declarations on repeated module passes. Body emitters reuse the same handle, with a fallback when the signature pass was absent. |
| `InstanceGetters`, `InstanceSetters`, `StaticGetters`, `StaticSetters` | Separate storage/dispatch sides; instance CLR property names use the PascalCase convention and static dispatch uses the original source name. Accessor declaration updates the relevant dispatch view; constant computed keys intentionally replace earlier named dispatch entries in source order. |
| `PreDefinedMethods`, `PreDefinedAccessors` | Body lookup aliases to the same method builders, keyed by emitted type name and CLR method name. They support predeclaration/body separation rather than defining a second method. |
| `AccessorBuilders` | Accessor AST reference identity takes precedence for body emission. Duplicate accessor names intentionally have different builders/bodies; name dispatch selects the last definition without appending both bodies to one method. |
| `TypedPrimitiveInstanceMethodCores`, `TypedPrimitiveMethodCoreBuilders` | Class/member dispatch and method-AST views of the same eligible private primitive companion. The public virtual object ABI is a separate method. Analysis chooses eligibility; body emission fills both bodies and direct dispatch uses the core only with its existing proof. Absence means the ordinary ABI. |
| Expression `StaticFields`, `StaticMethods`, `InstanceMethods`, `Getters`, `Setters` | Expression AST identity selects independent member maps. Declaration initializes them, signatures publish handles, and expression body emission consumes them. Named expressions with the same observable name still have distinct type owners. |

Inheritance resolution returns the declaring member and class by walking `Superclass`;
default-parameter overload selection remains in the existing overload owner. Missing
members remain optional lookups for inherited/dynamic fallback. Computed/property dispatch
registries already check duplicate declaration, missing body and late registration;
those completed owners remain intact.

Construction remains open through script/module body and initializer emission, including
late class construction and computed registration. Finalization completes the checked
owners and creates class types after bodies. No guest field value is frozen by metadata
completion. There is no demonstrated duplicate authority requiring a member-map rewrite.
