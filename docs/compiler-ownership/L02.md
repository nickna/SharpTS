# L02: Function and nested-scope closures

Resolves [#1890](https://github.com/nickna/SharpTS/issues/1890) by retaining the existing
compilation-local authority. The immediate producer/consumer inventory is
`artifacts/epic-1865/L02-source.txt`.

| Stores | Owner, identity and legitimate writes |
| --- | --- |
| `FunctionDisplayClasses`, `FunctionDisplayClassCtors`, `FunctionDisplayClassFields`, `FunctionAstNodes` | `ClosureCompilationState` for one compilation. Qualified function names, qualified class/method keys, or synthetic async-arrow keys select the owning callable. The AST map bridges name lookup to reference-based capture analysis. Declaration builds the type, constructor and actual field membership together; contexts borrow those same builders. |
| `AsyncCapturedVarsExclusion` | Per-callable analysis decision before function-DC declaration. Read-only state-machine captures and renamed read-only shadows are excluded; captures written by async children are promoted to reference storage. Unioning exclusions is analysis, not a second field owner. |
| `ArrowFunctionDCFields`, `ArrowFunctionDCSource`, `ArrowFunctionDCFieldRenames` | Child-arrow AST reference identity selects its relay field, owning function key and source-name-to-storage-key map. Read/write renames keep block shadows distinct while retaining outer fields. The body resolver applies the remap before accessing shared storage. |
| `AsyncArrowDCKeys` | Async-arrow AST identity maps to a unique `$asyncArrow$N` key, registered before propagation. It gives nested synchronous writers one reference DC on the async state machine. Absent entries mean no promoted storage is needed. |
| `ArrowScopeDisplayClasses`, `ArrowScopeDisplayClassCtors`, `ArrowScopeDisplayClassFields` | Owning arrow/inner-function AST reference identity. `DefineScopeDisplayClass` is idempotent for an existing owner and omits empty/per-iteration-only membership. Repeated runtime calls instantiate different DC objects from the same metadata. |
| `ArrowScopeDCFields`, `ArrowScopeDCSource` | Child-arrow AST identity selects the relay and owning callable AST. Capture-source records, rather than first matching variable names, resolve the owner; propagation passes the reference through intermediate closures. Extra ancestor references are separate access paths to those same owners. |

See [`ILCompiler.Functions.cs`](../../src/SharpTS/Compilation/ILCompiler.Functions.cs),
[`ILCompiler.ArrowFunctions.cs`](../../src/SharpTS/Compilation/ILCompiler.ArrowFunctions.cs),
and [`ILCompiler.Async.cs`](../../src/SharpTS/Compilation/ILCompiler.Async.cs). Function and
method DC declaration precedes global capture propagation; every module is collected before
scope DCs and relay fields are declared. Bodies then select the actual field maps, avoiding
claims about excluded loop bindings. Types are finalized after bodies in both script and
module compilation. An early generic registry freeze would interfere with these phases
without demonstrating a defect.

These maps describe distinct emitted artifacts and intentional aliases, rather than rival
ownership of guest values. Sibling closures share one invocation's storage; per-iteration
cells and separately invoked factories remain distinct. No metadata immutability rule is
applied to mutable guest variables. Unsupported nested async writes retain their explicit
compile rejection (`NestedAsyncArrow_WritesCapture_RejectedInCompiledMode`), with the
interpreter's expected result preserved; this audit does not claim to implement that feature.

Verification: `L02` passed **230** tests, including sibling factories, writes across await,
outer/inner shadows, per-iteration captures, ancestor relays and saved-IL execution tests.
`L02-modules` passed **83** cross-module and ordinary inner-function tests; zero failed/skipped
across both selections. Evidence is recorded in their logs/TRX under `artifacts/epic-1865`.
Both backends and independent compiler instances are exercised by the existing regressions.
No production change was needed for this boundary.
