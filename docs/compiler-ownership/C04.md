# C04: Lock decorator fields

Resolves [#1886](https://github.com/nickna/SharpTS/issues/1886) with a narrow owner-key fix
and retention of the six distinct field stores. Inventory: `artifacts/epic-1865/C04-source.txt`.

[`DefineClass`](../../src/SharpTS/Compilation/ILCompiler.Classes.cs) analyzes lock requirements
and owns all six maps by the generated class's **full CLR name**. The instance group contains
`SyncLockFields` (`object`), `AsyncLockFields` (`SemaphoreSlim`) and `ReentrancyFields`
(`AsyncLocal<int>`). The static group contains `StaticSyncLockFields`, `StaticAsyncLockFields`
and `StaticReentrancyFields` with corresponding static fields. Selecting either lock kind
declares that entire group's fields; these are separate storage roles, not duplicate handles.
Undecorated classes intentionally have no group.

Instance constructors initialize sync object, semaphore `(1,1)` and reentrancy storage before
guest constructor execution. Static initialization creates the corresponding group before
guest static field/initializer effects. Each instance has separate lock objects; the static
group is shared only by its declaring CLR type. Context aliases retain the original metadata
maps. Async stubs copy the selected owner's lock references into their state machine; nested
calls share the intended reentrancy tracker, while field values remain runtime state.

Inspection found sync-instance and async-instance lookups using `TypeBuilder.Name` where
declaration used `FullName`. A namespaced class therefore omitted synchronous lock cleanup,
and its async stub could miss the lock references. Both immediate consumers now use the
full declaring type name. Static consumers already use the qualified class key. Field types,
declaration order, signatures and locking/reentrancy algorithms are unchanged.

The initial failing namespace test is preserved in `C04/C04-namespace-before.trx`.
[`LockDecoratorOwnershipTests`](../../tests/SharpTS.Tests/CompilerTests/LockDecoratorOwnershipTests.cs)
now checks lock cleanup, actual async execution, absent undecorated fields, independent
instances/classes/compilations and same-named module owners in both import orders. It pairs
script IL verification with execution. Construction ends at script/module type finalization;
no early map freeze or freeze of guest lock state is introduced.
