# C03: Typed CLR properties

Resolves [#1885](https://github.com/nickna/SharpTS/issues/1885) by retaining per-compilation
property construction. Producers are
[`ILCompiler.Classes.Properties.cs`](../../src/SharpTS/Compilation/ILCompiler.Classes.Properties.cs)
and the expression declaration/property paths in
[`ILCompiler.Classes.ClassExpressions.cs`](../../src/SharpTS/Compilation/ILCompiler.Classes.ClassExpressions.cs).
Inventory: `artifacts/epic-1865/C03-source.txt`.

| Named stores | Ownership and order |
| --- | --- |
| `PropertyBackingFields`, `ClassProperties`, `PropertyTypes` | Qualified class plus PascalCase property name. `DefineClass` initializes the per-class maps before fields; `DefineInstanceProperty` resolves the type, records it, defines the backing field/property and attaches typed getter/setter bodies. These are different CLR artifacts for one property, not interchangeable authorities. |
| `DeclaredPropertyNames`, `ReadonlyPropertyNames` | Per-class sets derived from the source property declaration. Readonly still gets a constructor-initialization setter, but that setter is excluded from public property/direct dispatch. Required constructor writes remain possible. |
| `ExtrasFields` | Qualified class owns its dynamic storage handle; the class state uses the same handle for `$IHasFields` emission. Class expressions retain per-instance storage; eligible declarations can use lazy weak instance storage. Guest values are mutable independently of these metadata references. |
| `ExplicitAccessors` | Class/property name owns getter/setter/type tuples built during signature declaration. Getter and setter can arrive separately and intentionally complete the tuple. Constant computed accessors update dispatch in source order. |
| Expression `BackingFields`, `Properties`, `PropertyTypes`, `DeclaredProperties`, `ReadonlyProperties` | Expression AST reference identity owns separate property maps initialized before field construction. The CLR type's generated identity separates same-named expressions. Contexts receive both declaration and expression views, not a merged simple-name map. |

Static source fields use distinct static-field stores, not instance property backing fields.
Declared fields and generic-parameter-backed properties deliberately use dynamic storage
when typed `$IHasFields` conversion would be invalid. Missing typed metadata therefore
permits the existing dynamic/inherited path; it is not automatically a missing declaration.
Property names and readonly checks walk the existing class ancestry.

Metadata remains compiler-local and shared by reference into body contexts. Creation of
late/nested classes stays possible until the script/module finalization phases; typed
getter/setter bodies are often emitted immediately, while explicit bodies and constructor
initialization follow later. Reflection.Emit type completion closes construction. There is
no conflicting property authority demonstrated by these immediate paths, and no early
freeze or name/representation conversion is introduced.

Verification: **86 + 76 passed**, zero failed/skipped, in `C03` and `C03-properties`.
The runs cover same-named module expression owners with IL and execution, existing checked
property metadata failures, static/generic fields, auto-accessors, external CLR property
access, lazy typed-property initialization and dynamic-property semantics. C01 additionally
executes ordinary/expression property behavior in both backends. Logs/TRX:
`artifacts/epic-1865/C03*`. This is a retention outcome, not a new property semantic fix.
