# I01: Mapper and generated representations

Resolves [#1896](https://github.com/nickna/SharpTS/issues/1896) with checked configuration
identity and retention of the checked union/shape contracts. Inventory: `I01-source.txt`
under `artifacts/epic-1865`.

[`TypeMapper`](../../src/SharpTS/Compilation/TypeMapper.cs) owns fixed module/provider
references, an external declaration registry and lazily created delegate adapters. Its
three setters previously accepted replacement or foreign configuration without checks.
`I01-before.trx` preserves three failures for a foreign class module, foreign mapper's
union generator and foreign runtime module. A cached delegate emitter would otherwise
retain the old runtime while the mapper reported a new one.

Configuration now rejects null inputs and replacing an installed owner. Repeating the
same reference is allowed. Runtime metadata must belong to the mapper's module; the union
generator must belong to this exact mapper. Class builders remain a live alias to the
compiler's declaration dictionary for forward/body-time declarations, but initial values
and later consumed classes must belong to the mapper's module. Failed checks leave the
original owner/cache usable. External CLR types deliberately have a separate checked
registry and are not subject to the generated-class module restriction.

Runtime setup follows runtime emission; delegate access before it remains an explicit
failure. Class/union configuration follows user declarations and precedes strict interop
mapping. Primitive/dynamic mapping can precede optional class/union availability. Setters
bind owners, rather than freezing generated builders or copying away live declarations.

[`UnionTypeGenerator`](../../src/SharpTS/Compilation/UnionTypeGenerator.cs) retains its
mapper/module and validated Value-interface contract. Canonical union keys own types and
source-type conversion handles. It checks foreign modules and missing/late creation,
preserves existing forward handles after finalization, and marks completion only after
all types finalize. [`ObjectShapeRegistry`](../../src/SharpTS/Compilation/ObjectShapeRegistry.cs)
retains canonical-key and exact-CLR-type views of one declaration, protected dictionaries,
selected-key membership, duplicate checks and complete selected-set validation. Shape
selection/declaration completes after promotion analysis; actual types finalize after bodies.

[`DelegateAdapterEmitter`](../../src/SharpTS/Compilation/DelegateAdapterEmitter.cs) retains
one mapper-owned module/runtime/provider and a CLR-delegate-type-keyed cache. Each cache
miss emits constructor/Invoke bodies and finalizes its adapter before returning handles;
same-signature consumers reuse them. Counter names distinguish closed delegates with the
same short name. Typed delegate signatures and boxed guest-call invocation are different
ABIs; adapter construction emits no SharpTS.dll dependency. Guest callable/shape/union
values remain runtime data, independent of these completed declaration catalogs.
