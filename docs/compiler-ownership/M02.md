# M02: Enum compile-time metadata

Resolves [#1895](https://github.com/nickna/SharpTS/issues/1895) by retaining the existing
compilation-local views. Inventory: `artifacts/epic-1865/M02-source.txt`.

[`DefineEnum`](../../src/SharpTS/Compilation/ILCompiler.Enums.cs) owns the only writes to
`Members`, `Reverse`, `Kinds` and `ConstEnums`. Keys are module/namespace-qualified enum
identities; M01's path-owned prefixes also apply here. One declaration builds its member
table and numeric reverse table locally, computes kind from that same traversal, then
publishes all three views together and records const membership. Duplicate numeric values
intentionally replace reverse names in declaration order; string values have no reverse
entry. These are different facts derived by one producer, not independent declaration owners.
Contexts borrow the same maps through base/child factories. `Kinds`/`ConstEnums` currently
have no operational readers beyond their context plumbing; they are retained state, not a
newly enforced runtime contract.

Declaration completes before body/property/export consumers. Missing metadata is an optional
miss for non-enum expressions. Ordinary enums additionally own a `ValueFields` slot: the
runtime declaration initializes/extends a live object, and property/reverse reads use that
value when present. The compile-time table is not a substitute for guest mutation or an
enum's pre-declaration value. Erased const-enum reads and namespace/export materialization
can use metadata where no ordinary value binding exists. Reopened ordinary declarations
share the same value-field handle while each runtime declaration applies its own members;
their most recent compile-time snapshot is not a full guest-object state model.

Both script and module pipelines declare enum metadata before use and finalize containing
types after bodies. Retaining these compiler-private construction tables avoids introducing
a premature builder freeze or making guest enum objects immutable. Numeric/computed/reopened
runtime semantics remain with the explicitly assigned [#1788](https://github.com/nickna/SharpTS/issues/1788)
through [#1791](https://github.com/nickna/SharpTS/issues/1791); this bounded ownership decision
does not claim to repair or redefine those semantics.

Verification selection `M02` covers numeric/string/heterogeneous/const declarations,
computed const values, missing members, signed values, namespace reverse mapping, live enum
bindings and emitted enum runtime IL/execution. M01 also verifies same-named enum exports
from same-basename modules in both import orders and independent compilations. Counts and
execution expectations are preserved in `M02.log`/TRX: **124 passed, zero failed/skipped**.
No production change was required.
