# R15 — Workers and cross-context values

Outcome for [#1882](https://github.com/nickna/SharpTS/issues/1882): all five roots have
verified ownership. Message queues, foreign-value caches and explicit entry configuration
are intentionally retained. No specific ownership action is deferred.
The [shared conventions](README.md) apply.

[EmitAll](../../src/SharpTS/Compilation/RuntimeEmitter.cs) supplies canonical
EventEmitter/EventLoop/StructuredClone peers and completes these owners after deferred
bodies. Channel/worker/registry closure construction fields and BCL concurrency handles
remain local inputs to emission. Consumers use the same required/optional components;
no competing generated metadata owner is retained by the reusable emitter.
Non-null handle replacement follows these owners' declaration policy; completion
seals metadata while queues/cache/context values remain mutable.

The focused tests save, verify and execute generated output and preserve current
cross-context identity semantics. Cluster's test deliberately executes entry validation
without starting subprocess workers; no full cluster supervision or interprocess
failure-policy claim is made. General structured-clone/worker compatibility remains
outside this fixed ownership cohort.
