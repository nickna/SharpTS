# R01 — Calls and function values

Outcome for [#1868](https://github.com/nickna/SharpTS/issues/1868): all eleven roots
have verified metadata ownership; the mutable output-local caches and invocation
contexts below are intentionally retained. No unresolved ownership action was found.
The [shared evidence conventions](README.md) apply.

## Root dispositions

All eleven owners are required, get-only children of one `EmittedRuntime`; each is
fresh per `EmitAll`. Builder setters are single assignment and completion seals them.
The source links contain the exact handle inventory and completion checks.

## Producer and consumer boundaries

The orchestration points are in [RuntimeEmitter](../../src/SharpTS/Compilation/RuntimeEmitter.cs)
and [RuntimeEmitter.RuntimeClass](../../src/SharpTS/Compilation/RuntimeEmitter.RuntimeClass.cs).
[TSFunction](../../src/SharpTS/Compilation/RuntimeEmitter.TSFunction.cs),
[function wrappers](../../src/SharpTS/Compilation/RuntimeEmitter.Functions.cs),
[prototype population](../../src/SharpTS/Compilation/RuntimeEmitter.FunctionPrototypePopulate.cs)
and [invocation](../../src/SharpTS/Compilation/RuntimeEmitter.Objects.Invocation.cs)
use construction-local records and helper builders. Their lifetime ends with emission;
none substitutes for a canonical owner. Compiler closure/constructor sites read
`FunctionConstruction`, reflected super calls read `ReflectedMethods`, and dynamic
call sites read `Invocation`. The boundary tests assert explicit helper inputs and
absence of the removed flat runtime aliases.
