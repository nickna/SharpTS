# Raw numeric update transport (#3138)

An update of an `any` value has the checked TypeScript result `number`, but JavaScript ToNumeric can retain BigInt. Inferred double locals and typed source parameters must not convert that actual value merely because of the checked result type. The original function-local reproduction verified successfully and printed `number bigint false`; Node and the interpreter print `bigint bigint true`. The otherwise identical top-level control already passed.

The compiler captures actual update expressions, source callable parameter records and the checker's reference-keyed binding snapshot before lifting. A separate numeric representation fact follows the existing raw slot/return fixed point and exact rewrite/token relationships. It does not change checked types. It remains distinct from actual raw-call evidence and cannot create stable/native callee authority. Existing update read, conversion, receiver and write-back code is unchanged.

Possible callable values are a negative storage analysis. Only an actual const lexical binding with a wholly known source producer set narrows its possible parameter cohort. Mutable, imported, parameter, member/index, overwritten or otherwise unknown targets retain unknown exposure. When a raw numeric argument reaches such a target, every actual emitted source parameter remains possible; absence of an observed escape excludes nothing. This can conservatively box unrelated source parameters in programs with uncertain numeric arguments. Ordinary numeric code without an uncertain update producer does not activate this graph.

The inventory reuses the actual source-class emission predicate and excludes ambient/mapped CLR bodies. Foreign MethodInfo/ParameterInfo signatures and manually defined runtime interface contracts are not rewritten. Source declarations and their call sites use the existing parameter resolver and published raw representation facts consistently, including lifted, generic, async, constructor and override owners. Rest parameters retain their List<object> marker. Actual raw-result argument sites cannot select a static numeric/literal rest companion or numeric packing merely from a checked `number` type; the existing runtime numeric-rest capability still checks actual double values.

Validation includes the original and top-level controls, member/index updates, mutable and const callees, member/index calls, closures, call/apply/Reflect, async/generic parameters, constructor parameter properties, source overrides, rest/spread, both compiler pipelines, and mapped/foreign signature controls. Saved IL is verified before execution. Pinned TypeScript/Node comparisons cover ordinary language sources; CLR integration is checked against its actual metadata and runtime behavior.

Raw values also veto typed record promotion and direct numeric operator selection at actual affected sites. Unary minus/complement spill once, run the existing ToNumeric conversion, and retain Number or BigInt; unary plus keeps ToNumber and its BigInt rejection. Tagged templates and setters are actual argument ingress sites, and container propagation keeps destructuring and parameter-property reads consistent with the source ABI. The original negative-literal equality acceptance rows remain unchanged; their independent baseline failure is tracked as #3144, alongside companion runtime-BigInt construction checks.

The isolated handoff preserves the original 39 CLI rows: 37 pass and the two #3144 negative-literal checks fail independently on the frozen baseline. Four additional transport controls pass, giving 41/43 on the final CLI; all 42 ordinary sources match pinned TypeScript/Node. The affected 569-case suite has 565 passing cases and four failures consisting solely of those two sources in both saved compiler modes. Six unaffected programs, including an ordinary numeric call loop, retain all 6,901 method bodies, PE sizes and normalized PE hashes. The independent #3144 repair must replay the unchanged original acceptance rows before claiming complete verification.
